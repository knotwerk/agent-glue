# Contributing

## Ground rules

- Node 22 and npm. Install with `npm ci`; do not change dependencies without
  saying so in the change description (versions are pinned exactly).
- Keep Sessions and Companion independently packageable: no `require` across
  `packages/*`, no shared runtime files, no `extensionDependencies`. Companion
  talks to Sessions only through its optional activation API.
- Keep changes scoped to this standalone repository. Use a topic branch and
  pull request when contributing from a fork.
- Never delete files or terminate processes as part of development tooling.

## Tests must be hermetic

- Never interact with real agent terminals. Inject tmux responses (stub
  `core.sessions` / `core.run`, or pass an `exec`), and use the fake VS Code host
  in `test/host.test.cjs`. `scripts/test.cjs` puts a failing `tmux` shim first on
  `PATH` and fails the run if it is ever called.
- Never read real CLI conversation histories, credentials or memory
  directories. Use synthetic fixtures only.
- Create temporary fixtures with `test/support/tmp.cjs`. They live under
  `_script_outputs/test-tmp/` (git-ignored) and are intentionally never deleted.
- Browser tests (`preview-browser.test.cjs`) use a local headless Chromium found
  via `AGENT_GLUE_CHROMIUM` or the Playwright cache and skip when none exists.
  They serve only in-memory pages and abort every other request.
- A known gap is recorded as a `todo` test with the reason. Remove `todo` when
  fixing it.

## Before delivering a release

```sh
npm ci
npm test
npm run check
npm run package
```

Keep long output with timestamped logs, for example
`npm run package 2>&1 | tee _script_outputs/$(date +%Y%m%d_%H%M%S)_package.log`.

Then:

1. Inspect `dist/vsix/*.vsix` contents (the package step prints the audited
   file list) and make sure no runtime output, private screenshots, inbox
   contents, credentials or VSIXs are staged.
2. Run the manual acceptance checks below.
3. Do not install or replace your active extension until compatibility and host
   checks have passed.
4. Publish only after inspecting the staged files (`git status`, `git diff
   --cached --stat`) for private material.

## Where things live

| Area | Files |
| --- | --- |
| Tmux/files/uploads logic | `packages/companion/src/core.cjs` |
| Preview sanitiser and webview | `packages/companion/src/preview.cjs` |
| Sidebar markup | `packages/companion/src/views.cjs`, `media/` |
| Companion host wiring | `packages/companion/src/extension.cjs` |
| Sessions host | `packages/sessions/extension.js`, `helpers/` |

`dist/` in each package is generated by `npm run build`; never commit it.

## CI

`.github/workflows/ci.yml` runs `npm ci`, `npm test`, `npm run check` and
`npm run package` on Node 22 for Ubuntu and macOS. It does not publish and does
not upload artifacts.

## Documentation images

The two PNGs under `docs/images/` illustrate the top-level README: the sidebar
and the PR-to-rendered-document workflow. They use actual webviews with synthetic
data, not private conversations or project screenshots. To regenerate them:

```sh
npx playwright install chromium
npm run screenshots
# Or use an existing binary:
# AGENT_GLUE_CHROMIUM=/path/to/chromium npm run screenshots
```

The generator serves assets from memory, blocks external requests, and never
connects to tmux or VS Code. Keep its fixtures synthetic.

## Manual acceptance

Use a disposable Git project, separate VS Code profile, and tmux sessions created
for the test. Do not use active agent terminals. Record the VS Code/server/OS
versions, VSIX versions and failures in ignored development output.

- Install Sessions and Companion on the SSH host; verify each also activates
  independently. The bundled UI helper belongs locally. Reload without errors.
- Attach named test sessions, rename a tab, disconnect/reconnect and reload.
  Sessions must remain alive and reattach without duplicates. Workspace
  `.vscode/tasks.json` must remain unchanged.
- Switch terminals across projects and nested directories. Check discovery,
  per-session filters, newest-first ordering, pins and Show more up to 100 files.
  Unchanged polling must preserve keyboard focus; opening HTML must keep its row.
- Open Markdown with a local image, Mermaid and a table, then interactive HTML.
  Verify main-editor placement, document links and anchors. Outside-root assets
  and remote subresources must stay blocked. Documents over 25 MB must fail clearly.
- Download through the native Save dialog, cancel it, and check byte-for-byte
  contents. Native downloads must work without ZeroTier. Test optional browser
  links separately on a private ZeroTier network.
- Upload a file and use the Mac clipboard-image action. Check ignored inbox files
  have private permissions. Reject oversized files and a non-ignored inbox.
  Switching terminals during a batch must not change its recipient.
- Dictate into the note field on a Mac with the required permissions. Copy and
  paste must preserve the chosen recipient; paste must not send Enter. Closing
  a draft or removing an attachment must not delete the saved file.
- Review a synthetic local packet and hosted test PR. Check grouping, document
  previews, read marks and sorting. Save local feedback and verify it persists.
  Post to GitHub only in an explicitly authorized disposable test PR.
- Set up task instructions in the scratch project. Check active/blocked/review/done
  records, timestamps, malformed-record warnings and updates after refresh.
- Verify both safe CLI defaults and separate account-directory conventions when
  exercising restart. Reconnecting a live session and restarting a lost process
  are different operations.

## Publishing status

The Marketplace descriptions, screenshots and search metadata live in each
package’s README and manifest. The `knotwerk` publisher must be owned and
authenticated before submitting them. In the Marketplace publisher portal,
create a VS Code extension from each reviewed Sessions and Companion VSIX.
The local helper is bundled with Companion and needs no separate listing.
Never put publishing credentials in this repository or in chat.

Source and VSIX checks do not publish anything. Use a reviewed release and complete
native acceptance before claiming stable Marketplace support. Confirm publisher
ownership and local-helper installation during release preparation.
